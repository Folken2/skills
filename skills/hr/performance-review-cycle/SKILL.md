# Performance Review Cycle

## Overview

Run a structured, fair, and actioned performance review cycle. The core principle: **the review cycle is a system, not an event.** The meeting itself is the smallest part — everything before it (goal setting, evidence collection, calibration) determines whether the output is honest and useful or a bureaucratic surprise.

Grove HR and Talstack both find that the most common review failure is sporadic, unfollowed-up input from unprepared reviewers. The antidote is a gated cycle where each phase produces verifiable output before the next phase can start: self-review → manager draft → calibration → conversation → plan.

Reviews serve two purposes: **evaluation** (compensation, promotion, performance documentation) and **development** (growth, coaching, feedback). These purposes pull in opposite directions — an employee being evaluated for a raise cannot also be coached with full openness in the same conversation. Where possible, separate the two: the evaluation conversation confirms the outcome; the development conversation explores the path forward.

## When to use

- You are starting or running a performance review cycle (quarterly, semi-annual, or annual).
- You need to set SMART goals or cascade OKRs for a review period.
- You are collecting self-reviews, manager reviews, or 360/peer feedback for an upcoming cycle.
- You are running a calibration session to ensure rating fairness across a team.
- You are preparing for or conducting a review conversation.
- You are producing development plans as the output of the review cycle.

## When NOT to use

- You are managing day-to-day 1:1 cadence, continuous feedback, stay interviews, or retention checks outside of review season → use [[employee-engagement]].
- You are processing a performance improvement plan (PIP) or disciplinary action → involve HR and legal directly; a review cycle is not a substitute for a documented PIP.
- A compensation decision needs a market benchmark (salary band, equity refresh) → use the compensation-connection step (step 7) but source benchmarks separately.
- You are making an immediate termination decision → skip the review cycle and use [[employee-offboarding]] with HR and legal oversight.
- The employee is still in the 30-60-90 onboarding ramp → use [[employee-onboarding]]; performance reviews start after day 90.

## Workflow

### Phase 1 — Pre-cycle (2–4 weeks before cycle opens)

1. **Set the review cadence and communicate it.** Define the cycle calendar with hard deadlines: goal-setting start, self-review due, manager review due, calibration session dates, review conversation window, and comp decision date. Communicate the timeline, purpose, inputs collected, confidentiality rules, and rating scale to all participants before the cycle opens. A transparent rumor-free rollout prevents the anxiety spiral that derails review seasons.

2. **Train managers on the process.** Run a brief manager training session covering: the rating scale with behavioral examples, evidence standards (what counts as proof vs. opinion), bias-awareness (recency, halo/horns, similarity, leniency/centrality), the SBI feedback model, and escalation paths for disputes. Untrained managers produce inconsistent ratings that require heavy calibration rework.

### Phase 2 — Goal setting (start of period or as the cycle opens)

3. **Set or confirm goals for the review period.** For each employee, confirm 3–5 objectives using the SMART framework (Specific, Measurable, Achievable, Relevant, Time-bound). Goals cascade from company → team → individual where applicable, or use OKR alignment. The employee has meaningful input into their own goals — imposed goals lack ownership. Document each goal with a success criterion that can be objectively verified at review time. Common failure: goals set vaguely ("improve customer satisfaction") rather than measurably ("increase CSAT from 4.0 to 4.4 by end of Q3").

### Phase 3 — Continuous feedback collection (throughout the period)

4. **Gather feedback and evidence.** Throughout the review period, collect evidence against each goal. This is the phase most often skipped under the "I'll remember at review time" assumption — you won't, and recency bias will distort what you recall. Use a lightweight running log: one sentence per noteworthy observation, tagged by goal. Also collect input from peers and cross-functional stakeholders (360-style) where the role benefits from multi-source perspective. Give feedback *to* the employee in the moment, close to the event — reviews should contain no surprises.

### Phase 4 — Self-review (cycle opens, 1–2 weeks before review conversations)

5. **Employee completes self-review.** The employee reflects on each goal: what they accomplished, what challenged them, what they learned, and what they need. Self-review is completed *before* the manager writes their own evaluation — reading the self-assessment first surfaces manager blind spots and reduces the "I didn't know they faced that blocker" gap. Self-review is not the employee's formal rating — it is input for the manager's evaluation.

### Phase 5 — Manager evaluation (1–2 weeks before review conversations)

6. **Manager writes the review.** Draft the evaluation against each goal from step 3, using the evidence logged in step 4. Apply the **SBI model** (Situation, Behavior, Impact): describe the specific situation, the observable behavior, and the concrete impact. Avoid unanchored labels ("you're not proactive") — replace them with behavioral evidence ("when X happened, you waited for direction rather than proposing an approach; this delayed the decision by two days"). Rate each goal independently, then derive an overall rating from the pattern, not from averaging. The SBI model is credited to the Center for Creative Leadership.

### Phase 6 — Calibration (after manager reviews, before review conversations)

7. **Run calibration sessions.** Calibration is a meeting of managers (usually by department or level) who review ratings together for fairness. The HRBP or compensation partner facilitates. For each disputed rating, the manager defends with evidence; the group adjusts where ratings are inconsistent across teams. Calibration does not produce a consensus score by averaging preferences — it aligns ratings to a shared standard so one manager's "exceeds" is not another's "meets." Goal: a distribution that reflects actual performance, not a forced curve. Document the calibration outcome and any rating changes, including the rationale.

### Phase 7 — Review conversation (1–2 weeks after calibration)

8. **Conduct the review meeting.** Structure the meeting: (a) employee shares their perspective first — their self-assessment often surfaces what the manager missed; (b) manager shares evaluation, starting with strengths and what's working before discussing gaps; (c) two-way dialogue on ratings and evidence — invite questions, acknowledge the employee's experience; (d) agree on the development priorities and action items; (e) confirm the next check-in date. Keep to 45–60 minutes. If compensation is not part of this conversation (recommended: separate conversations by at least a few days), say so clearly so the employee knows what to expect and when.

9. **Document the conversation.** Write a summary of what was discussed, agreed actions, and any rating disputes. Both manager and employee sign off (or acknowledge digitally) within a few days. The signed review is the official record for compensation decisions, promotions, and future reference.

### Phase 8 — Development planning (within 1–2 weeks of the review)

10. **Build a development plan from review output.** Identify 1–3 growth areas surfaced in the review. For each, define: target skill or behavior, concrete actions (training, stretch assignment, mentoring, shadowing, certification), support the org provides, owner (employee, manager, or shared), review date. A development plan is not a wish list — it is a time-bound commitment with accountable parties. Link it to the growth plans maintained in [[employee-engagement]] step 4 and revisit it in 1:1s.

### Phase 9 — Compensation connection (separate conversation, after reviews)

11. **Communicate compensation outcomes separately.** If the review cycle feeds into merit increases, bonuses, or promotions, hold a separate conversation from the development review. The agenda: outcome only (no re-litigation of the rating), effective date, and new compensation terms. Separating these conversations lets the development review stay focused on growth and removes the adversarial dynamic of defending a rating while arguing over a raise. This follows the widely recommended "separate conversations" principle (Grove HR, Peoplebox, TinyTeam).

### Phase 10 — Cycle closure (within 1 month of reviews ending)

12. **Survey the cycle itself.** Collect anonymous feedback from managers and employees on the review process: Was the timeline clear? Did you have enough time to prepare? Was calibration fair? Was the conversation useful? Fix structural issues before the next cycle. Then archive cycle data (goals, ratings, calibration records, review documents, development plans) per the retention policy. Run the following cycle retrospective with the HR team: what went well, what didn't, what data was missing, what upstream process feeds this cycle.

## Red Flags / Common Mistakes

| Red flag | Why it's a problem | Do instead |
|---|---|---|
| Goals set vaguely with no measurable success criterion | Review time has no objective ground; ratings become personality assessments | Write every goal with a SMART success criterion that can be verified as met/not-met |
| Manager writes review from memory | Recency bias dominates; earlier contributions ignored | Collect evidence continuously (step 4) in a running log |
| Employee asked to self-review *after* manager review is written | Self-review becomes a rubber stamp; it surfaces no new information | Employee writes self-review first — it is input, not a response |
| No calibration between managers | One manager's "exceeds" is another's "meets"; inconsistent ratings damage trust across teams | Run calibration by department or level with an HR facilitator |
| Feedback delivered as labels ("you're not strategic") | No actionable path to improvement; feels personal rather than behavioral | Use SBI: Situation, Behavior, Impact — anchored to observable events |
| Development plan filed and never revisited | Growth doesn't happen; employee disengages | Link development plan to 1:1 cadence in [[employee-engagement]] |
| Compensation and development combined in one conversation | Employee defends their rating instead of listening to feedback; growth conversation fails | Separate conversations: development first, compensation later |
| Rating scale undefined or inconsistently applied | No shared standard; employees and managers interpret 3/5 differently | Train managers on the scale with behavioral examples before the cycle |
| Review cycle has no process feedback loop | Same problems repeat every cycle — missed deadlines, unclear forms, inconsistent quality | Survey participants and run a retrospective after every cycle |
| Hard deadline missed (self-review, calibration, comp decision) | Cascading delays; fairness eroded when some managers submit late | Build 1–2 week buffer between each phase; enforce deadlines with HR escalation |

## Exit criteria

- [ ] Cycle calendar published with hard deadlines for every phase, at least 2 weeks before the cycle opens.
- [ ] Managers trained on the rating scale, evidence standards, SBI model, and bias awareness.
- [ ] Every employee has 3–5 SMART goals set (or confirmed) at period start, with documented success criteria.
- [ ] Continuous feedback evidence collected against each goal throughout the period (running log).
- [ ] Self-review completed by every employee before manager evaluations are written.
- [ ] Manager evaluations drafted against goals using SBI model, with evidence from the running log.
- [ ] Calibration sessions completed, rating adjustments documented with rationale.
- [ ] Review conversations held, each with a signed/acknowledged written summary.
- [ ] Development plans produced from review output, with 1–3 growth areas, concrete actions, and review dates.
- [ ] Compensation conversations held in separate sessions from development reviews (if applicable).
- [ ] Cycle feedback survey collected and documented; retrospective run with HR team.
- [ ] Cycle data archived per retention policy; lessons applied to the next cycle.
